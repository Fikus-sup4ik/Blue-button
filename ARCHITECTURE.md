## Подтверждённая архитектура сейчас

На текущем этапе нет подтверждённых компонентов плагина, точек входа, зависимостей, сборки или рантайм-потока. README и INSTRUCTIONS содержат требования и предложения, а не доказательство существующей реализации.

Не проверены:

- загрузчик и версия Lampa, для которых предназначен плагин;
- способ регистрации кнопки на карточке;
- способ открытия собственного списка/окна;
- механизм сетевых запросов;
- контракт запуска потока;
- API Lampac или других источников;
- целевые платформы и ограничения их JavaScript-движков.

См. [API_DOCUMENTATION.md](API_DOCUMENTATION.md) для реестра доказательств.

## Предлагаемое устройство после подтверждения API

Это планируемое разделение ответственности, а не описание имеющегося кода:

1. **Bootstrap** — запуск после подтверждённой готовности Lampa и защита от повторной установки.
2. **Lampa bridge** — единственный слой вызовов к проверенным интерфейсам Lampa. Неподтверждённые глобальные имена и методы не добавлять.
3. **Интеграция карточки** — получение метаданных карточки и отображение одной кнопки через подтверждённый механизм расширения.
4. **Реестр адаптеров** — список включённых источников, их возможности и статусы проверки.
5. **Адаптер источника** — преобразование конкретного подтверждённого API в общий формат. Для каждого адаптера хранить ссылку на первичный источник доказательства и проверенный пример ответа.
6. **Поисковый координатор** — параллельные запросы, индивидуальные таймауты, отмена и частичные ошибки.
7. **Нормализатор и дедупликатор** — сохранить неизвестные данные как неизвестные; группировать вероятные совпадения, не теряя варианты источников, качества и озвучки.
8. **Представление результатов** — состояния загрузки, частичного результата, пустого ответа и ошибки с поддержкой фактически нужных способов ввода.
9. **Player bridge** — передать выбранный объект только через подтверждённый механизм проигрывателя Lampa.
10. **Диагностика** — технические ошибки без токенов, cookies и секретных URL.

### Предлагаемая схема результата

Схема ниже является проектным контрактом. Она не совпадает с каким-либо доказанным API ответа:

- `sourceId`, `sourceName` — идентификатор и подпись адаптера;
- `title` — заголовок, если он присутствует в ответе;
- `contentType`, `year`, `season`, `episode` — только при наличии достоверных данных;
- `quality`, `audio`, `size` — только если это сообщает источник;
- `playback` — исходный объект/ссылка в формате, который ещё должен быть подтверждён для Lampa;
- `raw` — минимальные обезличенные поля для диагностики, не секреты.

Неизвестные значения не подставлять догадками. Не считать произвольный URL воспроизводимым объектом.

## Поток данных (предложение)

```text
Карточка Lampa
  -> подтверждённое получение метаданных
  -> кнопка через подтверждённую точку расширения
  -> поисковый координатор
      -> подтверждённые адаптеры источников
  -> нормализация
  -> группировка совпадений с сохранением вариантов
  -> список результатов
  -> подтверждённый вызов проигрывателя Lampa
```

Каждая стрелка остаётся неподтверждённой до проверки реализации/документации и воспроизводимого испытания.

## Ограничения реализации

- Не добавлять интеграцию источника, пока не зафиксирован его реальный запрос и ответ.
- Не использовать код старого проекта без покомпонентной проверки происхождения, поведения и совместимости.
- Ошибка одного адаптера не должна терять успешные результаты других.
- Повторный поиск и закрытие UI должны освобождать слушатели и по возможности отменять запросы.
- Не хранить секреты в репозитории и не исполнять код источника.
- Сборка, формат модулей и целевые платформы пока не выбраны и не проверены.

Обновить этот документ, когда появятся доказательства: исходный код Blue-button, версия/источник API Lampa, проверенные контракты источников, решение по целевым платформам и результат реального теста полного сценария. До этого статус проекта — аудит/проектирование, не работающий плагин.
